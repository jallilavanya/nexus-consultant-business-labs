# AI engineering log

## Prompt themes

The five engineering prompt themes represented in this implementation are:

1. Define three independently runnable AI-consultant services behind clear HTTP interfaces.
2. Build a polite sitemap-syncing knowledge service with persistent retrieval and human escalation.
3. Provide a typed inbox classifier, evidence-backed drafts, and conservative operator-feedback automation.
4. Convert meeting transcripts into effort estimates, proposals, and explicit follow-up scope differences.
5. Integrate the services in an accessible dashboard with runnable evaluations and honest system documentation.

## Edge-case handling and explicit boundaries

- Invalid request bodies fail schema validation rather than receiving success-shaped fallbacks.
- Unknown knowledge questions return a low-confidence answer and create a stable unresolved task.
- Sync tracks sitemap `lastmod`, bounds concurrent page fetches to five, retries failures with jittered exponential backoff, replaces removed chunks within updated pages, and deletes pages absent from the live sitemap. One failing page makes the sync report failure instead of claiming a clean complete sync.
- A page with no `lastmod` is fetched on every sync; no destructive purge occurs if sitemap fetch itself fails.
- Screenshots are retained as source URLs even when no vision key exists. Image descriptions are indexed only when Anthropic is configured. Unsupported image MIME types are skipped; failed descriptions are logged.
- The `0.7` confidence score threshold is explicitly a workflow threshold, not a calibrated statistical guarantee.
- No matching index is an explicit unknown, not an answer based on imagined documentation.
- Feedback categories have independent approval streaks. Edits/overrides reset the streak, increment penalties, and disable existing auto-send eligibility. The demo never delivers actual email.
- Meeting transcript extraction is heuristic; missing explicit feature phrases falls back to a small number of transcript sentences for review rather than producing a fabricated empty success.
- Requirement fit depends on the Knowledge API confidence and must be reviewed when the evidence is insufficient.
- Identical task titles are the scope-diff matching key; modified tasks preserve their before/after representation.
- Pricing uses the configured hourly rate, defaulting to `$125` per hour, and must be approved before it is treated as a quote.
- Runtime benchmark numbers are intentionally generated by tests at execution time. No unrun model-comparison or performance result is reported as fact.
- Authentication, durable audit history, persistent inbox feedback, and actual email sending are not included and are documented as production blockers.
